# 要件定義: スマホ表示でヘッダーのボタンを非表示にする

- 作成日: 2026-11-24
- 対象: Worktable のヘッダー（`app/page.tsx`）
- ステータス: 確定（2026-11-24）

## 1. 背景・目的

スマホ幅ではヘッダーのボタン（メディアを追加・Instagram投稿）が「話す／書く」の切り替えと重なって表示される。スマホではメディア追加とInstagram投稿を使わないため、スマホ幅では表示しないようにして、ヘッダーを見やすくする。

## 2. 対象と非対象

- 対象
  - スマホ幅（md 未満）でのヘッダーのボタン表示
- 非対象
  - PC幅（md 以上）の表示・動作
  - ログ生成、メディア追加、Instagram投稿の処理そのもの（API・状態管理）
  - 「話す／書く」の切り替えの動作と見た目
  - スマホからの代替投稿手段（スマホからは投稿しない）

## 3. 現状（確認済み）

- 「ログを生成」：`hidden ... md:block` のため、md 未満ではすでに非表示
- 「メディアを追加」：全幅で表示（非表示指定なし）
- 「Instagram投稿」：全幅で表示（非表示指定なし）
- 「話す／書く」：タイトル行の中、全幅で表示

## 4. 機能要件

| ID | 内容 | 根拠 |
|---|---|---|
| R-01 | 「メディアを追加」は md 未満（スマホ幅）では表示しない。md 以上では従来どおり表示する | Q1で「隠す」と回答 |
| R-02 | 「Instagram投稿」は md 未満（スマホ幅）では表示しない。md 以上では従来どおり表示する | 依頼どおり。Q3で「スマホからの投稿は不要」と回答 |
| R-03 | 「ログを生成」は md 未満で非表示のまま変更しない | Q4で「現状のままでよい」と回答 |
| R-04 | スマホ幅で「話す／書く」の切り替えがボタンと重ならず、常に表示される | 依頼の「書く・話すにかぶってしまっている」を解消するため |
| R-05 | md 以上（PC幅）では、ヘッダーのボタンの表示・並びを変えない | 既存仕様の維持 |

## 5. 制約

- スマホ幅の基準は Tailwind の `md`（768px未満をスマホとする）で統一する（Q2の回答）。既存の「ログを生成」と同じ基準
- 非表示にするだけで、ボタンの処理（クリック時の動作・無効化条件）は変えない

## 付録A: 学習ノート用

- 目的・経緯：スマホで使わないボタンが「話す／書く」と重なって見づらいため、スマホ幅では隠したい
- 検討した案
  - A案：スマホ幅で対象ボタンを隠す（採用）。使わないボタンを消すだけで済む
  - B案：ボタンを折り返す、またはメニューにまとめる。全部残せるが、スマホで使わない機能まで見せることになる
- 決定事項
  - 「メディアを追加」「Instagram投稿」はスマホ幅で非表示。スマホからは投稿もメディア追加もしない
  - スマホ幅の基準は md（768px未満）で統一
  - 2026-11-25：検証で指摘された抜けを補うため、AC-06・AC-07を具体化し、AC-08・AC-09・AC-10を追加（ステータスは確定のまま）
- 残課題
  - 実機での表示確認
