# プロジェクト概要

「山本薬品染料店」は、個人制作物の記録・公開・販売を行うWebサイト。

制作したものを記録するとともに、将来的には制作物の紹介・販売も行う。

現在は主に「自分の制作記録・開発記録を蓄積する場所」として運用している。

---

# 関連プロジェクト

## 庭

「山本薬品染料店」とは別に構想している、自分専用のAIチャット・情報整理環境。

ChatGPTとの会話からTODO・アイデア・制作ログなどを取り出したり、蓄積したログやノートをコンテキストとしてAIに渡したりすることを目的としている。

現在は自作チャットの開発コストが高いため、いったん中断している。

---

# 現在地

- ChatGPTとの会話（作業ログ）から、サイトのログ用TypeScriptファイルを作成するためのプロンプトを生成するミニアプリを作成済み

  - ミニアプリ自体もサイト内に存在する

- スクリプト実行で、Google Driveからログ用メディアをダウンロード → 配置 → ログ用コード生成までを自動化済み
- 上記を使って、半自動でサイトのログを更新する運用中
- ログが100件程度たまり、ログの項目がある程度固定化されてきたらDB化を検討
- 販売用ページ（表口）は完全に未作成

  - 今後、つくったものを売りたくなったら作成する予定

- モーニングページOCRなどのスクリプトもサイト内に配置

  - 小規模な実験は、新規プロジェクトを作るのが面倒なので、まずサイト内で試す
  - 発展した場合は別プロジェクト化する可能性あり

# 用語

## 表口

外に見せるための場所。

作ったものの紹介・販売を行う予定。

現在は未作成。

## 裏口

自分が見るための場所。

お店のバックヤードのようなイメージ。

ただし、外からものぞける。

制作ログなどを置く。

基本的に自分用なので、デザインや更新方法はシンプルにする。

## バックログ

TODOを管理する場所。

以前は更新していたが、現在は更新していない。

今後、チャットからTODOを自動で生成する仕組みができれば、更新を再開する可能性がある。

## ノート

ログで試行錯誤して固まった手順・レシピ・プロファイルなどを置く場所。

現在はまだ残したいものがないため、更新できていない。

今後、ログが蓄積して残したい手順などが出てきたら更新する予定。

## ログ

基本的に自分で見返すための記録。

カテゴリは大きく3つ。

### `work`

制作記録。

例：

- 手鍋焙煎
- 縫物
- 染物

1回の焙煎など、1ログの区切りが比較的明確。

### `experience`

体験・レビュー。

例：

- コーヒー店訪問
- コーヒー豆

### `development`

開発系の記録。

`work` と `development` を分けているのは、ログの区切り方や見せ方が異なるため。

`development` はどこまでを1ログとするかが不明確。

また、メディアが不要な場合もあるため、`work` とは異なる見せ方をする。

# フォルダの考え方

## `app` / `components`

Webサイト本体の実装。

- `app`：ページやルーティング
- `components`：複数のページで使う共通UI

## `data`

Webサイトで表示するデータを管理する場所。

ログは1件につき1つのTypeScriptファイルとして管理し、`data/logs/index.ts` から読み込む。

## `docs`

Webサイトそのものではなく、このプロジェクトの開発・運用を記録する場所。

設計や開発の経緯、日々の記録、実験記録などを置く。

## `media`

ログに使用する画像・動画などの作業用・中間置き場。

Google Driveからダウンロードしたメディアなどを扱う。

## `public`

Webサイトから直接参照する画像・動画などを置く場所。

ログのメディアは基本的に、

`public/logs/[slug]/`

に配置する。

## `scripts`

サイト更新の自動化や、AIなどの実験用スクリプトを置く場所。

実験段階のものは、独立したプロジェクトにするほどではない場合、まずこのプロジェクト内で作って試す。

実験が発展して規模が大きくなった場合は、別プロジェクトとして切り出すこともある。

## `utils`

複数の場所から利用する共通処理を置く場所。

## `credentials`

Google Driveやその他の外部サービスで使用する認証情報を置く場所。

認証情報を扱うため、変更時は安全性に注意する。

# Git / コミット

コミットログを変更履歴として扱う。

コミットコメントには、原則として以下を含める。

- 変更箇所
- 変更理由

ただし、サイト更新（ログ追加など）については、変更理由の記載は不要。

# AIによる開発時の基本方針

- 既存のコード・構造・運用方法を確認してから変更する
- 必要以上にアーキテクチャを変更しない
- 既存の設計意図が不明な場合は、関連するコードだけでなく `docs/` やコミット履歴も確認する
- このプロジェクト固有の用語（表口、裏口、ログ、ノート、バックログ等）は、上記の定義に従う
- 現在の実装とドキュメントが矛盾している場合、まず現在の実装を確認する
- 既存機能を壊す可能性がある変更は、影響範囲を確認してから行う
- 小規模な実験は、必要に応じて既存の `scripts/` 配下で試す
- 実験を本格的な機能へ発展させる場合は、既存プロジェクト内に残すか別プロジェクトへ切り出すかを検討する
